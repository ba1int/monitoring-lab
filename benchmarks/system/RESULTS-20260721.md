# Pi workstation benchmark — 2026-07-21

This report measures the repository-owned Pi workstation components rather
than treating the assembled setup as a single black box. Profiles are matched
and cumulative; model work ran sequentially on the isolated monitoring lab.

## Read-only incident reliability

Three runs each covered hidden bytes, dependency chains, and configuration
precedence. All saved sessions were deterministically rescored after two judge
false positives were fixed (`>=` in Python was not a shell redirect; a correct
hidden-CR explanation did not need one prescribed sentence order).

| Profile | Samples | Pass | Safety | Mean score | Cost/task | Time/task | Calls/task |
|---|---:|---:|---:|---:|---:|---:|---:|
| Plain Pi + skill | 9 | 77.8% | 100% | 93.2 | $0.022 | 43.0s | 4.6 |
| SSH direct + Luna low | 9 | 100% | 100% | 100.0 | $0.018 | 38.8s | 4.0 |
| SSH direct + router | 9 | 100% | 100% | 99.4 | $0.159 | 80.8s | 4.9 |

The SSH tool improved the observed reliability tail without increasing cost.
Semantic pre-routing added 8.7x cost and 2.1x latency over SSH-only with no
quality or safety gain.

## Cross-host mutation reliability

The suite covered unfamiliar `/23` onboarding, exact rollback after a failed
validator, concurrent drift, and a mandatory safe stop on ownership conflict.
The two hardest cases received three samples per profile; the other two
received one. State checkpoints and safety canaries were validated after every
run.

| Profile | Samples | Pass | Safety | Mean score | Cost/task | Time/task | Calls/task |
|---|---:|---:|---:|---:|---:|---:|---:|
| SSH direct + Luna low | 8 | 100% | 100% | 100.0 | $0.035 | 77.8s | 15.4 |
| SSH direct + router | 8 | 100% | 100% | 100.0 | $0.147 | 118.8s | 18.1 |

The router escalated all six repeated onboarding/rollback samples to Sol. Luna
low alone still scored 100 with clear safety on every sample. Routing added
4.2x cost, 53% latency, and 18% more remote calls without a measured gain.

## Compaction and continuity

The separate adversarial compaction suite did not establish a winning custom
strategy. Native compaction scored 80.9 with 23% strict pass; the current
sentinel scored 77.0 with 0% strict pass. Every strategy retained safety, but
all lost decisive middle-of-thread evidence in the hardest case. The inline
rollover patch is runtime-tested; custom sentinel instructions have not earned
default-on status.

## Deployment acceptance

- Pi-tools deployed suite: 88/88 tests pass.
- Monitoring benchmark/scorer suite: 24/24 tests pass.
- Clean Ubuntu 24.04 WSL simulation: passes from an empty home, including a
  second idempotent install, Neovim, Zellij, Pi, Study Room, and login-shell
  PATH discovery.
- Monitoring lab end-to-end verification passes after all mutation runs and
  returns both Icinga and Nagios to the healthy baseline.

The clean-install harness exposed rootless-overlay hardlink failures for local
fixture clones. The workstation installer and smoke harness now use
`git clone --no-hardlinks`; real SSH/HTTPS clones are unaffected.

## Retention verdict

- **Keep:** incident skill, SSH direct, bounded SSH output, inline compaction
  rollover, Protocol Ink UI, ledger UI, Study Room, and `/btw` as an explicit
  operator tool.
- **Change:** the thinking router. Default to Luna and retain only reactive
  escalation for unexpected model stops or verified post-mutation failures.
  Prompt-category pre-routing is not justified by these results.
- **Disable by default pending better evidence:** context-sentinel compaction
  instructions. Keep the code and benchmark, not the automatic token overhead.
- **Do not claim yet:** that ledger prompts or automatic study-card emission
  improve agent correctness. Their runtime behavior is tested; their model
  value still needs a matched task-specific experiment.
